# 项目定义

## 产品方向

Knoa 为个人、团队与组织提供可跨会话、跨 Agent 使用的记忆能力。资料是证据，记忆是由证据支持、可以持续修正的理解。记忆应保留来源，用户能查看、修改、撤销，并验证后续检索是否使用了正确版本。

## 已确认的起步结构

- 品牌为 **Knoa**，解析产品为 **Knoa Parse**。
- 仅拆两个代码仓库；主仓使用单仓多模块结构。
- 解析输出标准化证据，包括来源版本和页码、时间或文本位置，不承担长期画像与记忆价值判断。
- 主仓统一承载记忆、接入、工作台、适配、评测与整套部署配置。
- 技术栈尚未确定，本阶段不创建产品运行时与基础设施依赖。

## 建议的首个闭环

导入一份小型文本资料 → 得到可定位证据 → 提议并提交记忆 → 按空间检索 → 展示记忆及出处 → 修正记忆 → 验证新版本生效且变更可追踪。

此闭环是启动建议，尚未批准为完整产品需求。首批格式、空间权限、自动写入策略和部署形态见 [待决事项](decisions.md)。

## 长期方向

多模态资料解析、自然语言纠偏、跨平台接入、关联发现与周期整理、冷热管理，以及控制成本的上下文组织。它们保留在架构中，但不要求首个版本同时实现。

## 讨论依据与完整性

依据为用户在 2026-10-14 确认的命名与双仓方案，以及历史对话《拆分记忆系统架构》中可读取的最后五轮内容。可读取内容包含四仓到单仓多模块的调整，以及命名讨论；更早的完整需求没有取回。本文件不把未取回内容中的潜在约定视为已确认。
