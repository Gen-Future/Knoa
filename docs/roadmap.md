# 启动路线图

这是建议的工作顺序，不包含时间或交付承诺。

## M0：可开始实现

- [x] 明确品牌与双仓边界。
- [x] 建立目录说明、开发约定与 ADR。
- [x] 提供可校验的 Parse 契约草案与合成示例。
- [x] 编写本地检查与 CI 配置；远端执行需在推送后确认。
- [ ] 补回并核对早期完整需求，确认首个场景。
- [ ] 确认技术栈、首批格式、部署方式、授权基线及许可证。
- [ ] 冻结首条链路所需契约，建立运行时工程与锁文件。

验收：两仓各自检出后能独立检查；待决事项清楚；实现任务能定位到模块与验收样例。

## M1：一条记忆链路

建议先使用小型 UTF-8 文本，降低格式处理对记忆验证的干扰。

- Parse：来源版本 → 文本证据与位置 → 明确成功/失败。
- Core：空间、来源、证据、记忆与变更的最小持久化。
- Writing：由证据生成提议，确认后提交；重复执行不重复写入。
- Retrieval：在明确空间和授权下返回记忆、出处与版本。
- API/worker：组装导入与查询，报告任务状态。
- Console：最小浏览、查看证据、修改与撤销入口。

验收：导入、检索、纠偏、再检索与撤销可复现；错误和重试可观测；越权与旧版本召回有用例。端到端实现前，应先为这些行为建立验收案例。

## M2：接入与评测

接入一个真实 Agent 宿主，确定 HTTP/MCP 边界；建立小型去敏评测集，验证来源定位、记忆有效性、检索质量、纠偏效果与成本。

## M3：多模态与长期整理

按需求逐个增加 PDF、图片、音频或视频格式；加入部分失败策略与解析资源隔离。整理先产生可审计建议，再逐步开放自动提交，不绕过 writing。
